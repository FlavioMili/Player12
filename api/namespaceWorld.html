Detailed Description

Combining two world databases. Nothing different is ever merged or dropped automatically. Entities match only on a strong identity (names in the context of their parents, never by numeric id) that is unambiguous, with exactly one candidate on each side: identical matches merge silently, differing ones become conflicts the player resolves, and the children of a matched entity follow it (cascade). Weaker matches (same club name in another league, same player at another club, ambiguous keys, look-alike names) are added as new entities and flagged as possible duplicates.

World databases: one shareable JSON document ("*.fmdb") holding any subset of a football world (languages, regions, countries, cities, travel times, competitions, clubs, players and name pools). The built-in world and user worlds share the format, the loader and the validator. Unknown keys are preserved, so mods can carry extra data through the in-game tools unchanged. Format reference: assets/world/README.md.

Structural edits of a world database used by the World editor: new, duplicated and removed entities with every reference kept consistent. Travel rows have no id and are addressed by their position in the section.

The football geography of a world: regions (pre-season tours stay inside one) grouped into confederations (continental cups, national-team finals). A world without its own regions or confederations uses the built-in ones; a region without a confederation joins the first one, a country without a region belongs to the first region. Ids are the entities' ids (1-255).

The world the running (or starting) career is built from. A new career installs the world the player chose; loading a career installs the world stored in its save (the built-in world for saves made before world databases). Everything that reads world content (generation, club identities, name pools, league profiles, calendars) reads it from here.

Field specifications of every world entity. One table drives validation, the World editor's controls, conflict comparison and the template file, so a new field is declared once.
